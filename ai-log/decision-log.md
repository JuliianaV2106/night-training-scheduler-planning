## Highlighted Human Corrections of AI Testing Mistakes (Task Impl-2 Rubric Requirement)

During **Task Impl-2**, the human engineering team actively audited all AI-generated tests and implementation code against the BMad Test Engineering Architecture (TEA) rules, explicitly catching and correcting **4 critical AI testing/implementation mistakes**:

1. **Human Correction #1 (Entry #19 — Flow A ATDD Story 9.4: Rejecting Wall-Clock `sleep()` in Eviction Timeout Tests):**
   - *AI Mistake:* To test the 60-second `SIGTERM` (`05:45:00`) $\rightarrow$ `SIGKILL` (`05:46:00`) timeout in Story 9.4, the AI initially proposed a background timer with `time.sleep(1)`.
   - *Human Team Correction:* Rejected `time.sleep()` unconditionally. Enforced discrete-time stepping via `SimulatedClockAdapter` (`05:45:00-05:00` $\rightarrow$ `05:46:00-05:00` $\rightarrow$ `06:00:00-05:00`) injected into `HardEvictionSupervisorService`. The test executes in `< 15 ms` with zero wall-clock sleeps.
2. **Human Correction #2 (Entry #20 — Flow B Test-Along: Rejecting Over-Mocking of the Database/Domain Boundary):**
   - *AI Mistake:* An initial AI test draft proposed using `unittest.mock.MagicMock` on `SQLiteRepositoryAdapter` to assert `repo.cordon_node.assert_called_once_with("ws-gpu-14")`, which would have passed even if the SQL query or schema constraint was broken.
   - *Human Team Correction:* Enforced the **No Over-Mocking** rule. Replaced mocks with a real ephemeral SQLite instance initialized from `001_night_training_scheduler_schema.sql`. This immediately caught a real schema `CHECK` constraint gap (`EVICTED_FORCEFULLY` and `CORDONED_DIRTY` literals from Annex Story 9.4 were missing from the Solu-2 SQL `CHECK` constraint), which a mocked test would have hidden.
3. **Human Correction #3 (Entry #23 — Flow D `k6` NFR Load Testing: Rejecting `sleep()` Pacing & Fixing Write-Lock Contention):**
   - *AI Mistake:* In the first `k6` script draft, VUs ran in an unpaced `ramping-vus` loop (`1,134 req/s`) and acquired an exclusive SQLite `BEGIN IMMEDIATE` write lock even on read-only idempotent replays (`p95 = 153.14 ms` > `50 ms` target). To lower RPS, an AI suggestion proposed adding `sleep(0.5)` inside the `k6` default function.
   - *Human Team Correction:* Rejected `sleep()` in `k6`. Switched the `k6` scenario to the open-model `ramping-arrival-rate` executor (up to `200 iters/s` across `50 VUs` with zero sleeps) and refactored `JobSubmissionService.submit_job` to perform a lock-free read fast-path with double-checked locking inside `atomic_transaction()`. Result: **$p_{95}$ dropped from `153.14 ms` to `8.52 ms`** with `0.00%` failed requests (`5,221 / 5,221` checks passed).
4. **Human Correction #4 (Entry #25 — Flow E Playwright E2E Story 9.6: Rejecting `waitForTimeout()` & Enforcing Page Object Model):**
   - *AI Mistake:* Initial E2E draft included raw `page.locator('#list-running .job-card')` inside the `.spec.ts` file and proposed `await page.waitForTimeout(300)` after clicking `Fast-Forward to 22:00`.
   - *Human Team Correction:* Rejected `waitForTimeout()` and raw CSS selectors in the spec file. Created `test/e2e/pages/SchedulerDashboardPage.ts` encapsulating semantic `data-testid` locators and used Playwright's web-first auto-retrying assertions (`await expect(board.runningJobCards()).toHaveCount(5)` and `await expect(board.idleNodeCards()).toHaveCount(32)`), completing the full 24h time-lapse E2E test in `2.1 s` with forensic `trace.zip` capture.
